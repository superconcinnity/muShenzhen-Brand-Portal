# 主视觉延展：先建立正方形网格，再设计

适用于 mushenzhen 官方 main / Machines / Life / Intelligence 主视觉的比例延展。用户确认的基本要求：色块使用同一套正方形网格，符号遵循对应主题的颜色和符号族。不能仅模仿阶梯外形。

## 必须执行

1. 先选一个 theme：读取 [contract.json](contract.json)。main＝紫/灰/斜线/沙漏/深/圳；machines＝棕/米白/斜线/机器人/机/器；life＝蓝/米白/斜线/生命符号/生/命；intelligence＝粉/米白/斜线/星号/智/能。荧光绿与深色共用。官方主题延展不从其他主题借颜色或符号。合作方定制另议，不能把自创配色写成官方主题。
2. 设定单元边长 c、原点 (0,0) 和整数列/行数。每个基础单元 **c×c**；矩形色块可跨多个单元，但四边必须在整数格线上。长方形色块并非错误，**把基础格子横向拉长才是错误**。
3. 改画幅时重新安排格子的行列；不能将整张竖版压成正方形或把横版拉宽。目标像素不能整除单元时调整单元/行列或在网格外补边，注明补边。
4. 符号也占用同一网格的单元，原始形状等比缩放。一个格子一个完整图标；保留内部反白、边框、剪切。不可把 632×84 的整个组合条缩成一格，不可用 Unicode、字体或 AI 生成替代图标。四个 84×84 裁切窗口已在 contract.json 中提供。
5. 正式 Logo 直接引用 assets/logos 的对应 SVG，整组等比缩放。三排 Logo 内部的 50 单位构造网格与海报布局网格是两件事，不能把 Logo 拆开塞到海报网格中。
6. 先检查大形、负空间与信息层级，再布置成段符号和安静空格。网格正确不代表构图合格，不用随机散点掩盖大形问题。
7. 保留用户文案；原海报日期地点是历史内容。缺少本次信息不编造。无新照片授权时不用原主题海报内嵌照片。

## 直接制作

可复制 examples/*.json，换画幅、色块、符号、Logo 位置后生成 SVG：

```sh
python3 assets/key-visuals/system/compose.py assets/key-visuals/system/examples/main-square.json --out /tmp/main.svg
python3 assets/key-visuals/system/compose.py assets/key-visuals/system/examples/main-square.json --verify-svg /tmp/main.svg
```

配置的 blocks 与 symbols 坐标用**格子单位**，Logo 坐标/宽度用**画布单位**。blocks 可有整数 w/h；symbols 默认 1×1 格，可用整数 span 等比占据 n×n 格（大符号仍沿用同一格网）；颜色只能用本主题角色名，不能直接传另一个主题的 HEX。

该工具生成自包含 SVG；用可用的 SVG 渲染器导出 PNG，查看实际图片。英文 slogan 是普通信息文字，不是品牌 Logo，默认 sans-serif 仅作便携示例；正式排版可用仓库模板所附字体，不能宣称示例字体就是已确认标准。

## 交付检查与边界

交付配置、SVG、PNG 与网格说明，查看实际成品后再发布。工具检查整数格点、画幅、主题色/符号族、Logo 资产与等比变换、同色不可见符号（对 span 覆盖的每格做保守检查；复杂跨色背景的局部同色也会拒绝，应改位置/前景色或另做人工可见性审计）。`--verify-svg` 比较实际 SVG 与配置生成结果，避免只检查一份未用于成品的 JSON。

自定义 SVG 不能仅因为有 metadata 就声称通过本工具。文字碰撞、留白、密度、可读性、Logo 对比度和品牌神态仍需看图判断。本工具不是任意 SVG 的完整审计器。例子的列数、颜色面积、密度和排版不是新增的官方固定标准。

反例：1080×1080 用 30×20 网格会产生 36×54 基础格；正确做法如 30×30、每格36。1920×1080 可用32×18、每格60。1080×1440 可用30×40、每格36。斜线原始轮廓本身不必填满方格，但承载它的单元必须正方形。
