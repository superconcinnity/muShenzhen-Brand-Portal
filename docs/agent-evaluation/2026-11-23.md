# 主视觉 Agent 使用测试 · 2026-11-23

## 测试目的与方法

检验只拿到 GitHub 品牌包的 agent，能否做出正方形网格、主题色与符号匹配、字标正确的主视觉延展。基线提交为 `e4f94c12c06144f148beb668ed49b2ee67143ce5`。

三名不继承主对话上下文的 agent 完成四张图：main 1080×1080 方形封面、Life 1920×1080 横版、Machines 与 Intelligence 1080×1440 竖版。任务只提供仓库路径、尺寸、品牌名/slogan及无日期地点要求，没有提前提醒网格与主题约束。读取范围由指令限制，未做操作系统隔离；依据执行记录与报告评估，不能宣称抵抗恶意越界。

第二轮以同样的三个任务交给三名新的无历史 agent，仅提供改进版品牌包路径。第二轮进行中工具补充了可选整数 span（允许大符号用 n×n 格）及第三符号窗口 316 的核对，三名 agent 收到同一维护提示。这意味着本轮是有记录的迭代复测，不是严格冻结工具的实验。

## 第一轮实际发现

| 作品 | 网格 | 主题 / 字标 | 其他证据 |
|---|---|---|---|
| main 方形 | 45px、24×24；色块与35px图标按格居中，符合基础方格组织 | 主品牌紫/灰及深/圳/沙漏/斜线；官方字标 | 主动找到了工具目录中的单符号视窗线索；已修复过 fill=none 遗漏 |
| Life 横版 | 背景60px网格清楚；焦点图标 x1190/y310/490px 自设尺度，未声明其与同一网格的关系 | Life蓝与对应符号；主品牌官方字标；Life为字体标题且报告说明 | 程序按索引抽取 strip 子路径，增加人工核对成本；已对照原条带，生命符号的环缺口属于源图形，不能误判为损坏 |
| Machines / Intelligence 竖版 | 自述120px侧栏格；阶梯起点y444、侧栏x876等与该格原点关系未定义；可事后细分更小格解释，但原方案未交付共同构造网格，判“无法充分验证”而非断言所有矩形都错误 | 棕/粉及各自符号族正确；官方主/主题字标 | 使用多种自设尺度；也曾修复 fill=none 导致框字黑块 |

颜色与主题族四张都基本选对，不能把本次结果写成“旧仓库全军覆没”。三个执行报告均记录了根节点 fill=none 丢失引发的图标错误，并自行修复；这是资产使用接口容易出错的直接证据。不同 agent 都要自行猜裁切窗口，也增加重复劳动与几何丢失风险。

## 改进内容

- 根级 AGENTS.md、README、AGENT-GUIDE、GUIDE 提供明确的主视觉延展入口。
- `assets/key-visuals/system/README.md` 明确基础方格、色块整数格点、符号占格、等比重排、主题绑定以及 Logo 内部构造网格与海报布局网格的区别。
- contract.json 将 main / machines / life / intelligence 的主题色、辅助色、符号名和原条带窗口放在同一处。色值保留已有来源含义，用户确认的是主题匹配与正方形构造要求。
- compose.py 保留整个源条带并用正确视窗裁切，保留 fill=none、反白、边框与剪切；实例ID加前缀，防止多个图标剪切ID串用。Logo只支持等比宽度缩放。
- 四个可运行配置覆盖方形、横版和竖版。它们是起点，不是用户已确认的固定版式。
- 检查器验证配置并可比较实际导出的 SVG；15项测试包含错误输入和篡改后的SVG。检查范围在README明确，不声称自动证明美学、文字碰撞或任意自定义SVG正确。
- 同步动态GIF已收录状态、静态字体目录与模板附字体的说明；不把演示照片授权扩大。

## 评判边界

这一小样本使用相同运行环境中的模型实例，不代表不同厂商、不同模型、低能力agent或任意自然语言需求的普遍成功率。前后作品的构图好坏仍需要品牌方审阅。工具通过只能证明其覆盖的结构约束；不代表海报已获官方设计批准。没有强制所有图都用30列、相同色彩面积、同一符号密度或同一模板。

## 第二轮结果

[打开四组前后对照](gallery.html) · [总览图](comparison.png)。图片为审阅缩略图，成品与配置保留在本地测试目录。

| 作品 | 明确网格 | 实际导出验证 | 主题资产 |
|---|---|---|---|
| main 正方形 | 30×30，36px单元 | 主检查器检查配置；因 slogan 用仓库字体转曲，agent另用完整SVG再生成比较，并检查Logo留白 | main紫/灰和完整符号族，原始主品牌字标 |
| Life 横版 | 32×18，60px单元；大符号也以整数span跨格 | compose --verify-svg | Life蓝/米白与生命符号、生/命，原始两套字标 |
| Machines 竖版 | 整数方格配置，包括大图标占格 | compose --verify-svg | 棕/米白与机器人、机/器，原始字标 |
| Intelligence 竖版 | 整数方格配置，包括大图标占格 | compose --verify-svg | 粉/米白与星号、智/能，原始字标 |

主 agent 实际查看了两轮共八张图片；复测主题配色和源符号图形可辨，未见黑块覆盖框字。原始生命图标的左下环缺口保留，不能将它误判为生成错误。复测在结构与来源可验证性上更稳定，不据此推导美学评分或跨模型成功率。

本次不把四张复测海报升级为已确认正式模板。公开提交只包含规则、工具、四个起点配置和对照报告缩略图；原有官方Logo、符号条带、静态主视觉原稿均未修改。

人工审阅仍有可改之处：Machines复测的主题字标与slogan间距约40px，小于H/2约56px的建议留白。该项是使用建议而非本次硬性网格规则，已由agent报告保留，不宣称所有建议均通过。

复测精确需求及复现注意见 [PROMPTS.md](PROMPTS.md)。

## 独立审查与最后验证

另一名审查agent发现 span 大符号可见性只检查左上格的漏洞。已改为对整个占格区域做保守前景/底色检查，添加对应反例，最终15项测试通过。三张直接生成的SVG与方形定制转曲SVG均重新核验，实际图形输出未因检查增强改变。该检查会保守拒绝部分跨色背景的局部同色情况，README已注明。
